# 旅游列车跨部门开行

协调旅游列车的铁路运行资源、地方接待与旅客变更。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括铁路客运部门、地方文旅部门、旅游服务商、团体旅客，以及铁路调度人员与平台客服人员两类协作角色。

资料所依据的领域事实如下：

- 铁路部门主动对接各地文旅部门设计旅游列车线路
- 前八个月累计开行二千五百零一列旅游列车
- 旅游列车分为旅游专列与旅游专线列车，两类须保持清晰分类
- 增开旅游列车须同时满足铁路运行图、车辆检修、景区接待与地方活动档期
- 宣传页面可提前售卖，线路施工或客流不足仍可能引发临时调整
- 普通客运系统无法解释整条旅游产品为何变更
- 开行协作平台统一管理线路方案、停站时刻、车底与乘务资源、景区容量、团体合同、售卖批次与应急预案
- 线路冲突、车辆故障、活动延期、跨午夜运行、部分退团与替代景点仅允许调整受影响行程段
- 方案调整须同步通知已购票旅客
- 调度人员可见铁路安全约束，文旅部门掌握地面接待承诺
- 客服可从每次改签或退款还原方案版本与责任来源
- 开行后须核对实际客流与服务兑现情况

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
